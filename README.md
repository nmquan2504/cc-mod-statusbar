# cc-mod-statusbar

A Claude Code mod that draws a clickable status bar in the band above the prompt, in any project.

![The usage menu: rate limits, the automation, this session, and what fills the context window](docs/usage.png)

While Claude works, the empty middle of the bar plays a small arcade: monsters (each in a random color). Every tool call sends its own monster: Bash `ᗣ`, Edit and Write `Ѫ` (two hits), Read, Grep and Glob `⍤`, an MCP tool `Ӝ`, an agent `Ѯ`, a web tool `ᘛ`, anything else `⍨`; with no tool call for 4 seconds, monsters of the arena's own walk in at random intervals (0.5 to 3 seconds apart), each at its own random speed, and every 10 kills a slow boss (`Ѭ`, five hits) that bursts three cells wide. Claude (`¬✻`) at the right end fires `-` bullets at the monsters it has seen for a moment, and each kill bursts as `✺`. The number at the left counts the kills of this turn. The turn's clock and what it has cost so far (`◷ 1:12 $0.08`) head the right group, before the gauges. A turn of 10 seconds or more ends with a toast of its time and cost. The arena sizes itself to the gap, and when the prompt goes idle the monsters left burst, Claude stays on the field for 3 seconds, then the monsters and the count clear. Claude itself always stays at the right end of the gap (grey while idle), so its menu opens at any time; when the gap is under 16 cells Claude moves to the head of the right group. A number after Claude (`¬✻2`) counts the agents and the servers running for it, read every 5 and 10 seconds with the menu shut. A click on Claude opens what it is working on: after a turn of 60 seconds or more, a Last turn block first, where Haiku sums up what was done and how it came out (Did, Result) from the request, the tools run, the files changed and Claude's last message; then the tool it runs now, its task list (from `TaskCreate`, `TaskUpdate` and `TodoWrite`, and `TaskList` when the engine answers it) marked done, in progress or pending, the files the main loop wrote this turn with the lines added and removed (a pick puts one into the prompt, `o` opens the last one in VS Code or the default app), the agents still running, and the servers Claude started: every TCP port in LISTEN held by a process under this Claude Code process (a dev server from a background Bash, an MCP server), read with `ps` and `lsof` every 5 seconds while the menu is open. A click on a server opens `http://localhost:<port>`; a server started outside Claude stays out. The menu refreshes every second while it is open. A failed tool call sends a red boss `Ж` (the orange `Ѭ` is the boss that comes every 10 kills, and bullets do bring that one down) that bullets do not touch: it waits in front of Claude until the next call succeeds, and then bursts. A task marked done fires a volley that clears the field. A monster that gets through to Claude bursts on the gun as a hit: Claude shows red for about a second and the count reads `12 ✝ · 2 ✗`; the error boss never gets that close.

A click on the bar gives it the keyboard without highlighting `+`: the focus ring starts on nothing, and Tab moves it onto the items. A click on an item, or ctrl+x tab and Enter, opens its menu upward inside the frame; the same item or `✕` closes it. Escape hands the keyboard back to the prompt and leaves the menu open: a mod cannot catch Escape in the band. Inside a menu the digits press the entries. The `[-]` at the frame's right is Claude Code's own control for collapsing a plugin's band (also ctrl+x ctrl+a).

## In Claude Code for VS Code

The bar is not drawn in the extension's panel: the panel draws every button as its own bright native button whatever colors the mod asks for, and nothing drawn there came close to the terminal's look. The hooks still run there: the dangerous-command check, the vault, the guardrails readings, auto-continue and the `hi` schedule.

## On a narrow terminal

When the full bar would leave the arena fewer than 16 cells, the bar switches to its compact labels: the model as `S5.5`, the mode as its icon alone, the effort as its first letter, folder and branch cut to 14 characters, and the usage figures without gauges. If even the compact bar leaves no room, the arena steps out and Claude stands at the head of the right group. Either way the bar stays on one row.

## The tasks menu

![The tasks menu: the last turn's summary, what runs now, tasks, edited files, agents, servers and background commands](docs/tasks.png)

Claude's `¬✻` opens it: the last long turn's summary, what runs now, the task list, the files edited this turn, then:

- **Agents**: those running, then the last three that finished. A press opens one: the tools it called, in order (the last eight), and its answer once it ends. The mod keeps these from the agent's own tool calls and turn end, for this session (a reload starts the record over).
- **Servers**: the ports Claude's processes listen on, each asked over HTTP every 30 seconds whether it still answers (`✓ 200`; red when it does not answer or answers 5xx: `✘ no answer`, `✘ 502`; a server that is not HTTP answers nothing), each with its framework when its command line or the command that started it names one (Vite, Next.js, Django, Uvicorn, http.server and twenty more); a press opens one in the browser. A server that came from a command Claude left running in the background has a `log` chip beside it.
- **Background commands**: the last five Claude left running this session, each with its state (running, completed, failed, killed: the engine's task notification says how one ended). A press shows the last 15 lines of the command's log, the session's `tasks/<id>.output`, read again each time the menu redraws; `@` puts those lines in the prompt, `follow` keeps the newest lines in view (redrawn every second, as `tail -f`; shutting the log stops it), and `errors only` keeps the error lines alone. Each row counts its log's error lines (`3 errors`, from its last 200 lines); one that ended has `↻ rerun`, which runs the same command in the background again, through Bash as Claude would. Under a row: the addresses a running command printed (a dev server's Local and Network lines), each a press away in the browser; `? ask Claude` on one that failed or logged errors, which sends Claude its error lines and last lines to find the cause and fix it; and, when it could not listen (`EADDRINUSE`), the port and the pid that holds it now, with a `■ stop` for that pid. `■ stop` stops a running one through the engine's TaskStop, after a second press within 5 seconds; a server gets one too (a server no background command accounts for is stopped by its pid).

A background command that fails, or whose log shows an error line (`Error`, `Exception`, `Traceback`, `EADDRINUSE`, `failed`, `fatal`, `panic`; the logs are read every 5 seconds), turns a red `✘ npm run` chip on the bar; a press opens the tasks menu on its log, and the chip goes once seen.

## Settings

![The Settings menu: bar presets, the items on the bar with their order, switches and numbers, output style](docs/settings.png)

`+` then `s` (Settings) opens these rows. A digit or a click flips a switch, `−` and `+` step a number, `r` puts every row back to its default. Every change keeps the settings it replaced (the last 20, across sessions); `u` (Undo the last change) puts the one before back. The values are kept in this mod's store, for every session. `c` (Copy the settings) puts them on the clipboard as JSON, the bar's order included; secrets stay in the keychain and never go with them. On another machine, copy that JSON and press `p` (Paste settings): it replaces the settings in force, a key it lacks gets its default, and `u` brings the earlier ones back. Text that holds no settings changes nothing.

**Bar preset** heads the menu: three presets set every item at once, Full (all of them), Focus (all but the arena) and Minimal (model, usage, remote, shield); the one the switches match is marked. **On the bar** follows: one chip per bar item (model, effort, mode, folder, git, arena, usage, remote, images, mcp, guardrails), all on by default; the remote's `⇄` draws only while Self remote is on, and hiding it hides the chip, not the remote. A press hides the item and gives its cells to the arena; `+`, `⁄` and Claude's `¬✻` always stay. With the arena off, Claude stands at the head of the right group. The chips are listed in bar order, and the `‹` and `›` beside each one move it a place left or right. The arena chip divides the two groups, so an item moved past it changes sides. The folder and the branch share one button while nothing shown stands between them, and split into two once something does. Presets switch items on and off but keep your order. A saved order still as earlier versions shipped it, with the mode at the right end, takes the current default; an order you moved stays as you left it.

## Self remote

Its two rows have a group of their own in Settings, after the other rows and before the output style. With `selfRemote` on, `⇄` on the bar opens a menu that puts every Claude Code session on this machine on your phone or another browser. Start takes a second press within 5 seconds. It runs one hub for the machine (`remote/server.mjs`, in Node, started in the background so it outlives the session that started it) and one Cloudflare quick tunnel to it, so it needs `node` and `cloudflared`; a quick tunnel needs no Cloudflare account. Start looks for `cloudflared` first (on the PATH, then in Homebrew's folders) and starts no hub without it: the menu then offers Install with Homebrew (two presses; it runs `brew install cloudflared` with a spinner, then starts the remote), or, on a Mac without Homebrew, the link to Cloudflare's releases, and Check again. The menu then draws a QR code of the link. It shows the code 5 to 20 seconds after Start, once the tunnel's new name resolves, because a phone that asks too early caches the miss. The hub asks `trycloudflare.com`'s own name servers, which keep no miss: a public resolver asked before the name exists keeps the miss for the zone's negative TTL of 60 seconds, which made some starts wait over a minute. The code shows only after a Start from this session, and only until the menu shuts. Every other opening keeps it hidden, including the first one in a session that joined a hub already running, and `q` shows it.

Every session with the setting on joins the hub, from the terminal, the VS Code extension or the desktop app (a `-p` or SDK run, which nothing draws, stays off), and sends it a snapshot every 2 seconds: the folder and branch, the model and mode, the turn's prompt, the tool running and the tools run, the task list, the last turn's summary, the last 30 messages, the files edited this turn and the files git reports changed, the pasted images, and the usage figures. On the phone the page reads as a chat: your messages in bubbles on the right (a fenced block in one drawn as a code block, as in Claude's), Claude's on the left, and each tool call as one line (a press opens what it gave back, or an edit's diff; a tool still running reads brighter than those done; a call that failed offers, under its output, to ask Claude about the error, which quotes the call and what it said over the reply box). Held half a second, a bubble (Claude's or yours) starts to dim, and at a second and a half it is copied as written, or on a code block, that block. A swipe toward the middle (right on Claude's, left on yours) quotes it: a small card over the reply box shows who wrote it and its first two lines, `✕` drops it, and Send puts it before your reply as `> ` lines. ↑ and ↓ over Newest (all three drawn see-through, so the chat under them still reads) jump to your message before or after where you read. A code block whose fence names a language is coloured as the file viewer colours a file. It keeps whole turns, each from your prompt, the last 20 of them (Load earlier turns, atop the chat, asks the session for 20 more, up to 100: while they load the button spins and two grey bubbles shimmer under it, and when they come in the place you read stays put, the page eases up a little and the new turns fade in); a turn of more than 30 tool calls shows its last 30 and counts the ones before. A command sent from the phone sits where the session stood when it ran, with what it printed under it. A slash command typed in the terminal (`/reload-plugins`, `/compact`) and what it printed stay off the phone; a skill's turn shows as any turn. A prompt typed while Claude works is in no message of the session: the mod finds it in the request form of the messages (read again when the messages change, at most every 5 seconds while a turn runs and once when it ends), keeps it, and shows it after the tool call it came in with. Each `[Image #n]` in your bubble is a link that opens that pasted image. One line heads it: the drawer of sessions, the session's name (a press shows its branch, model, mode, folder with the home folder as `~`, usage and cost) and a button that opens four tabs. In the drawer each session takes three short lines, each cut to the drawer's width: its folder, its title (the name `/rename` gave it, else the one Claude Code wrote, read from its transcript), and its branch and whether it works. Its dot pulses while it works and turns amber while a question or a permission prompt waits for you there, and a ring at the row's end shows how full its context window is (amber from 70%, red from 85%). A session that ended a turn while another was shown gets a blue dot by its name, and the drawer's button one too, until it is opened. The drawer's foot names the mod's version the session picked loaded (`v0.15.1 · 994a88c`) and opens Settings. Settings is kept on the phone alone (its browser storage) and holds the page's language, English or Vietnamese (a phone set to Vietnamese starts in it; the hub's and the mod's messages, such as an error or a refused command, and the push notifications follow it, the service worker reading the language the page saved; Claude's words and the pages the mod builds come as written); the theme, light, dark or the phone's own; the size of the chat's and the code's text, from 85% to 150% with a preview (the file viewer and diffs too); the voices that read aloud, one Vietnamese and one English, each with a sample to hear, by default ZeroTTS's maichi once the Mac has it installed, else the best the phone has (Premium, then Enhanced, Apple's novelty voices left out), a voice picked there holding either way, and the speed; a switch for notifications; a switch that reads each notice aloud as it comes in while the page is open, by default a status in the page's language (Claude has responded, or Claude needs you, with the session's folder), else its title alone, the title and the message's first line, or the title and all of it (at a turn's end, Claude's whole last answer) (turning it on says so aloud; a browser lets a page speak only after a tap since it opened, so the first tap of each load says nothing aloud to be let speak later, and a notice still refused says why in a toast; a page in the background may not be let speak, and the push shows as ever); private notifications, on by default, which put only "Claude has responded" or "Claude needs you" on the lock screen and in the shade (the service worker reads the switch from the Cache Storage the page shares with it); a blur over the page while the phone shows another app, so its app switcher shows no chat (put on when the window loses focus, which comes before the page hears it is hidden and so more often before Android takes the switcher's picture, except while a select is open, the mic listens or a passkey prompt shows); a blur after 15 or 30 seconds, 1 or 5 minutes without a tap or a scroll, off by default, which a tap takes away without reaching what is under it, so a phone put down shows no chat in its app switcher either; an app lock that, after 1, 5, 10 or 30 minutes away, covers the page until the phone's own screen lock lets you through (fingerprint, face or PIN, asked through a passkey made for the link's address, so a new link sets it up again; a check in the page, against a person holding the phone), with notices read aloud as their status alone while it is locked; the paired devices, this one marked, each with when it was last seen and the others unpaired from here after a second press; What the phone is shown has its secrets masked first: the vault's values as `[secret:NAME]`, and any key-shaped string (GitHub, GitLab, Slack, Anthropic, OpenAI, Stripe, Google and AWS keys, JSON web tokens, private keys, a `.env` line naming a secret) cut to its first characters, in the transcript, the prompt, the tool running and a permission prompt's command. Everything between the phone and the hub is encrypted end to end, so Cloudflare, which carries the tunnel and ends its TLS, sees only the sizes and times of requests: not the files, diffs, prompts, transcript, paths or answers. The link holds a random 256-bit key K after `#`, which never leaves the phone. To pair, the phone sends an ECDH P-256 public key with an HMAC under a key derived from K; the hub answers with its own public key, a 4-character code (letters and digits) and an HMAC over both keys and the code, which the phone checks, so no one in between can swap the keys or the code. Both sides derive the phone's AES-GCM key from the ECDH secret salted with K, and the phone keeps it in IndexedDB as a key the page cannot export. The phone then waits until you pick, in a terminal's ⇄ menu, the code it shows: the menu offers three codes and says none is the phone's, so an Allow out of habit cannot let in a phone nobody looked at, and a wrong pick refuses the request. It waits a minute at most: the phone and the terminal's ⇄ menu and chip count the seconds down, and once the minute is over the hub drops the request, the phone says to scan again, and a pick made late is refused. Every call after that is one `POST /x` of a sealed body: the call, its arguments, the time and a nonce; the hub refuses one that does not open with that phone's key, one older than two minutes, and one it has seen before, and seals its answer to that call's nonce. A browser without WebCrypto is refused rather than served in the clear. A page saved to an iPhone's Home Screen keeps its own storage, so it pairs by pasting the link (`⇄`, then `c` to copy it).

The page's own HTML and scripts still come through Cloudflare. This protects against Cloudflare reading or keeping the traffic; it cannot protect against Cloudflare deliberately changing the page's script to take K, which no web page can rule out. Ten wrong keys lock pairing until the remote starts again, at most five phones stay paired, `f` forgets them all, and a stop or a restart makes a new key and a new address. The phone sees only what the snapshots hold: a diff is served only for a file a session lists, and an image only from the session's own images folder. The hub talks to the sessions over a Unix socket in `/tmp/qsb-remote-<uid>`, which only your user can open.

`h` takes this session off the phone's list and leaves the others. `x` stops the hub for every session, after a second press. The hub says which version of the mod it was started from; when a session loaded another (after a pull, say), the menu names both and `r` restarts the hub on that session's code, after a second press. A session whose code is newer than the hub's (by the commit's date) restarts it by itself, once a load, when no phone asks to pair; a session on older code never restarts a newer hub. A restart keeps the link and the paired phones. cloudflared runs detached from the hub, writing to `tunnel.log`, so it outlives the hub; asked to restart, the hub writes K, the phones it allowed with their keys, their push subscriptions, the VAPID key and its port to `state.json` (mode 600, in the hub's folder), and stops without stopping the tunnel. The hub started next reads that file once, deletes it, listens on the same port and takes the tunnel over, so a phone reconnects in about a second and is never asked to scan. A file older than 10 minutes, or whose tunnel is gone, is not used. A hub from before 0.14.4 cannot hand over: it restarts by itself only when no phone watches, and every phone scans again. Stopping the remote (`x`, the idle time, no session left) stops the tunnel and keeps nothing, and a hub killed outright leaves its tunnel to the next hub, which stops it. The hub also stops by itself when no session has called in for two minutes, or no phone has watched for `remoteIdleMinutes` (never, when that is off). Its log is `/tmp/qsb-remote-<uid>/hub.log`. Quick tunnels carry at most 200 requests at once and no server-sent events, so the page asks again (a long poll) and gets each change within a second or two. Each start has a new address, so a page saved to an iPhone's Home Screen works until the remote stops.

## Claude's questions

With Self remote on and its hub running, when Claude calls AskUserQuestion the mod answers the call itself and the engine's dialog does not open. The band opens a `? Claude asks` menu instead, with every question at once: each with its options (`( )` for one choice, `[ ]` for several; a digit picks the first nine), the preview of the option picked, and an Other box for an answer of your own. `s` submits and `d` dismisses; a question left blank is left out, and Claude reads the answers in the dialog's own words. One question with one choice and no previews (a permission prompt is one) needs no Submit, in the band or on the phone: a pick is the answer, sent with whatever the Other box holds. Shut the menu and a `? Claude asks` chip on the bar opens it again. With Self remote on, the phone shows the same questions on a page of their own and gets a push; the first answer in, from the Mac or the phone, is the one Claude gets, and the other side closes. With the remote off or its hub stopped, where no band draws (Claude Code for VS Code, a `-p` run), or while another question waits, the engine's dialog asks as before; in the VS Code extension a permission prompt still shows on the phone as a card to read, answered in VS Code. While a question waits, the hook sleeps in short `sleep` commands, as a hook's own time is capped at 10 seconds and a `$` call does not count against it.

With Self remote on and its hub running, a permission prompt is asked the same way: the mod's `tool.check` hook takes the engine's ask and puts it in the band and on the phone, as a `Permission` question with the whole command (or the file, or the URL) and the engine's reason. Yes runs the call; Yes, and don't ask again adds the rule "Asked most" would suggest (`Bash(mkdir:*)`) to `.claude/settings.local.json` and runs it; No refuses it, and text typed in the Other box goes to Claude as what to do instead. The engine's own dialog does not open for it. Deny rules, yours or the organization's, decide before the mod sees the call, and a call the organization caps at ask is left to the engine. Where Team and Enterprise organizations seat the built-in `cc-plugin-sec-default` plugin outermost, it checks such an answer against the engine's own verdict (the transcript then notes that the mod's `tool.check` hook was skipped); a Yes from the phone still ran the call at once, without a second dialog. The engine asks as before for a subagent's call, for AskUserQuestion and the plan tools, while another question waits, and in auto mode, where its classifier settles an ask first (an ask a plugin made, which the classifier cannot settle, is taken there too). Those prompts show on the phone as an orange card with the call and the reason, from a second after the dialog opens until it is answered, with no buttons: you answer them at the computer.

## Secret vault

`/secret [NAME]` asks for the value in a hidden macOS dialog (zenity on Linux) and stores it in the OS keychain under the service `cc-mod-statusbar-vault`. A known prefix (`figd_`, `ghp_`, `glpat-`, `xoxb-`, `sk-ant-`, `sk-`) names the secret and binds it to its API host. Any other value asks for a name, a host and a header. `/secrets` lists names and hosts, never values, and `/secret-forget NAME` deletes one.

Claude sees only the NAME. It calls `secret_list`, `secret_request` (opens the dialog) and `secret_fetch` (an HTTPS call that sends the secret only to its bound host and scrubs it from the response). After a WebFetch or WebSearch, `secret_fetch` allows GET only. A Bash command that names the keychain service or contains a saved value is refused. A token pasted into the prompt is saved and replaced by `[secret:NAME]` before the model gets the prompt.

The NAME-to-host bindings live in this mod's own store; the values stay in the keychain.

## Install

The repository is its own marketplace. Type this at the prompt of a terminal session, answer `y` to add the marketplace, then pick a scope:

```
/plugin install cc-mod-statusbar --marketplace nmquan2504/cc-mod-statusbar
```

The repository is private, so the account running Claude Code needs read access to it on GitHub. A copy installed this way updates through `claude plugin update cc-mod-statusbar`, then `/reload-plugins`.

## Where it lives

The author's copy sits in `~/.claude/skills/cc-mod-statusbar/`, a clone of the repository, so every session loads it as `cc-mod-statusbar@skills-dir`. A minute after a session starts, and every hour after that, the mod fetches its own repository. When the upstream has commits this folder lacks, a `↑ mod` chip shows at the head of the right group. A press runs `git pull --ff-only`, so a local change is never merged over, then `/reload-plugins`, with no question first. A folder that is not a git clone, such as a marketplace install, never shows the chip. The last line of Settings names the version the session loaded, read again by each `/reload-plugins`: the manifest's version, then the commit and its date (`0.15.1 · 994a88c, 23 Oct 10:41`). After a pull it adds that a newer version waits for `/reload-plugins`, and a reload that loads another commit says so in a toast, `now on` the new version and `was` the old one. A marketplace install shows the manifest's version alone. `v` (Check for update), just above that line, does the whole round at once: it fetches the repository, says so when nothing is new, else pulls fast-forward only and runs `/reload-plugins`, with no question first.

Changes are made elsewhere, in a separate clone at `~/Q/Projects/-/cc-mod-statusbar`, each on a branch of its own (`git fetch && git switch -c <branch> origin/main`). Every session watches `~/.claude/skills/cc-mod-statusbar` and reloads the mod when a file there changes. A reload resets the mod's state, so a question waiting in the band stops taking answers, and an edit saved halfway reaches every open session. To try a change live, start a session with `claude --plugin-dir ~/Q/Projects/-/cc-mod-statusbar`: a `--plugin-dir` copy takes the name, and that session skips the skills folder's copy. Other sessions get the change once its pull request is merged and the `↑ mod` chip pulls it.

```bash
claude plugin disable cc-mod-statusbar@skills-dir   # turn it off
claude plugin enable cc-mod-statusbar@skills-dir    # turn it back on
claude plugin validate ~/.claude/skills/cc-mod-statusbar
claude plugin test ~/.claude/skills/cc-mod-statusbar
```

Every lifecycle hook fails open: if the bar breaks, prompts and turns carry on and Claude Code draws the band without it.
